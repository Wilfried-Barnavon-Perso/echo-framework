# 🌌 ECHO Framework - Connaissance Sémantique : `11-owui-filters`

> **ATTENTION AGENTS** : Ce document est la base de connaissances sémantique exclusive du dossier `11-owui-filters`. Il complète les règles globales définies dans le `AGENTS.md` à la racine.

## 1. Rôle du Dossier

Ce dossier représente la **Conscience et l'Injection Contextuelle** de l'agent. Il contient les filtres Open WebUI (Inlet pour les requêtes entrantes, Outlet pour les requêtes sortantes). Leur rôle est d'altérer silencieusement la requête ou de réaliser des tâches asynchrones d'indexation sans bloquer la boucle d'événement.

## 2. Cartographie des Fichiers et Algorithmes

### `build_environment_domain.py` (Inlet - Priorité 0)
**Rôle** : Amorçage à froid de l'Environnement ECHO (v5.226.18.0).
- **Sémantique** : Filtre Inlet critique (priorité absolue 0). S'exécute avant toute logique applicative ou requête LLM.
- **Algorithme Clé** : Il est responsable de la création dynamique et de l'injection complète de l'arborescence du Framework en distinguant les Domaines Globaux (`ECHO_GLOBAL_DOMAINS` via `get_echo_global_path` : `skills`, `files`, `chats`, `n8n_workflow_templates`) et les Domaines de Session (`ECHO_SESSION_DOMAINS` via `get_echo_session_path` : `codex/main`, `codex/sandbox`, `files`, `n8n_workflows`, `dependencies`) dès la première interaction de l'utilisateur avec l'API WebUI. Il applique également un masquage strict (`chmod 0o711`) sur le dossier `files` pour empêcher son exploration directe par le LLM au sein de l'environnement isolé (`bwrap`).

### `conversation_rag_filter.py` (Outlet - Priorité 100)
**Rôle** : Pipeline d'Ingestion Conversationnelle Zéro-Latence (v5.226.18.0).
- **Sémantique** : Filtre asynchrone qui s'exécute après la génération de la réponse. Il découpe l'historique en fenêtres de tours de parole (turns) et les envoie au système d'Embedding (Qdrant).
- **Algorithme Clé** : Implémente l'**Upsert Idempotent Zéro-Latence** avec itération à rebours **O(1)** (anti-Fork Bomb lors du branching) en interrogeant `EchoStateManager.is_message_embedded()` (flag booléen `is_embedded` dans SQLite) *avant* toute communication avec Qdrant, et utilise l'ID du message assistant pour garantir l'indexation lors d'une régénération. Il intègre une gestion anti-zombie explicite des erreurs asynchrones via un callback (pour absorber `asyncio.CancelledError`), utilise un `unique_seed` pour éviter les doublons et bloque fermement les payloads Base64 (images).

### `new_context_filter.py` (Inlet - Priorité 30)
**Rôle** : Smart Context RAG Injector (v5.231.11.1).
- **Sémantique** : Intercepte la requête entrante, attend la libération d'un éventuel verrou de clonage de session (`await wait_for_chat_clone(chat_id)`), orchestre l'ingestion des fichiers attachés (`echo_ingestion.py`) et interroge Qdrant pour récupérer les souvenirs persistants.
- **Algorithme Clé** : Fusion sémantique qui préserve le score `memory_importance`. Assemble le `current_user_multipart_payload` selon l'ordre strict PGCU, et injecte les mémoires, la directive dynamique d'initialisation de session (PIS) ou de montée de version (`<artifact id="AEC_directive">` demandant de notifier succinctement le passage de `last_version` à `version`, persistée via `last_framework_version` dans `echo_settings`), ainsi que les événements système dans la structure **XML native et modulaire** (`EchoAEC`, `<artifact id="AEC_smart_context">`, `<artifact id="AEC_evenement_systeme">`) en associant des `source_id` pour la traçabilité. Fiabilise l'extraction de `_echo_user_msg_id` (fallback sur `metadata.user_message_id`) et `_echo_user_msg_updated_at` (fallback sur `int(time.time())`) pour garantir le scellement Shadow du message utilisateur. Intègre un fallback `from pytz import timezone` en cas d'absence de `ZoneInfo`.

### `app_drawer_filter.py` (Inlet - Priorité 1000)
**Rôle** : Interface Homme-Machine Flottante (v5.231.39.1).
- **Sémantique** : Filtre Inlet silencieux. Il n'altère pas la requête LLM mais injecte dans le DOM de l'interface Open WebUI un composant *Data Island* (le HUD ECHO App Drawer). Ce HUD communique en temps réel avec l'API WebUI pour déclencher des actions interactives (ECHO Codex, Agent Monitor) sans rechargement de la page, y compris pendant la génération du modèle (avec fallback direct vers `window.echoOpenCodex` ou `POST /api/chat/actions/<id>` lorsque le bouton natif n'est pas encore monté dans le DOM). Il intègre le support complet du **HUD Mobile** (déplacement tactile, persistance de la position `echo-hud-top`, et différenciation du seuil tactile `15px` vs souris `3px` pour prévenir l'hyper-sensibilité).

### `edge_embed_bridge_filter.py` (Inlet - Priorité 3)
**Rôle** : Déport de la puissance de calcul (Offload) et WebUI Bridge (v5.231.11.1).
- **Sémantique** : Intercepte les requêtes sur Desktop et déporte l'inférence vectorielle (`onnx-community/harrier-oss-v1-0.6b-ONNX`, quantification `fp16`, 1024D) vers le navigateur client via WebGPU/WASM et WebSocket (`/ws/edge-embed`).
- **Algorithme Clé** : Applique un **Bypass Serveur-Side sur Mobile** (inspection du header `User-Agent` via `ECHO_MOBILE_UA_PATTERN` court-circuitant toute injection JS sur mobile au profit du fallback CPU immédiat). Sur Desktop, s'appuie sur le générateur factorisé `EchoUI.get_edge_embedding_bridge_js` (`echo_ui.py`) qui exécute en amont la sonde matérielle et fonctionnelle **`window.echoProbeWebGPU`** (`navigator.gpu`, adaptateur physique non-fallback, extension `shader-f16`, limites de buffers $\ge 128\text{ Mo}$ et **Compute Smoke Test WGSL `f16`**) *avant* toute manipulation de cache, création du HUD ou téléchargement du modèle, et interrompt immédiatement le flux via `reportIncompatibleAndAbort` si le GPU est incompatible. Injecte le HUD d'initialisation WebGPU (piloté par `window.echoBindHudGeometry` et `ECHO_ICONS["Cpu"]`, décalé à `calc(50% + 125px)`) avec rechargement automatique de la SPA en cas de mise à jour du script et gestion multi-onglets (`client_id` UUID, `visibility`).

### `context_gauge_filter.py` (Inlet / Outlet - Priorité 10)
**Rôle** : HUD Contextuel de Tokens Persistant & Différentiel Dynamique (v5.231.28.1).
- **Sémantique** : Filtre bidirectionnel exécuté à la priorité 10 (après `edge_embed_bridge_filter` à 3, avant `user_native_context_filter` à 20). Déporte l'affichage et la mise à jour du HUD de tokens hors de l'orchestrateur pour garantir sa visibilité continue et son hydratation multi-phases, tout en ignorant les tâches de fond (`meta.get("task")`). Transmet `compaction_count` et `compacted_turns` au HUD contextuel.
- **Algorithme Clé** :
  - **Inlet (`is_pending=True`)** : Résout `(user_id, chat_id)` via `extract_closure_context(__event_emitter__)`, résout le modèle actif via `get_ca_model_id(sm.get_last_active_model())`, déploie immédiatement le HUD en mode attente avec anneau SVG pulsant dès le tout premier tour (même sur un chat neuf sans tokens enregistrés), puis, hors sous-tours d'outils (`role != "tool"`), fige l'état du tour précédent via `EchoStateManager.archive_previous_context_stats()` si un historique existe, ou initialise via `EchoStateManager.init_session_context_baseline()` la référence initiale du tour 1 (`totalTokenCount = 0`, quotas `quota_5h_fraction` et `quota_weekly_fraction` extraits depuis `identity.db`).
  - **Outlet (`is_pending=False`)** : Rafraîchit les quotas Cloud OAuth2 (`AuthService.refresh_quota_if_needed()`), intercepte les métriques fraîches consolidées par l'orchestrateur en base SQLite (`EchoStateManager.get_last_context_stats()`), enrichit et persiste `context_stats` avec les fractions de quotas fraîches (`quota_5h_fraction`, `quota_weekly_fraction`) via `save_context_stats`, extrait le tour précédent archivé (`get_previous_context_stats()`), et calcule via `EchoUI.calculate_context_delta()` le différentiel unitaire ($\Delta_{\text{total}}$, $\Delta\%_{\text{quota 5h}}$, $\Delta\%_{\text{quota hebdo}}$), la variation de capacité disponible ($\Delta\text{ Capacité}$ formatée à 2 décimales, perte en négatif et gain en positif : $\Delta\%_{\text{capacité}} = - \frac{\Delta_{\text{total}}}{\text{max\_tokens}} \times 100$) et le taux de croissance/variation du contexte indexé sur `promptTokenCount` (avec prise en compte explicite de `is_first_turn` pour afficher la capsule et les deltas de quotas dès le tour 1). Met à jour le HUD en temps réel sans latence avec intégration d'un tableau récapitulatif compact des quotas et des statistiques de compaction au survol.

### `context_compaction_filter.py` (Inlet - Priorité 25)
**Rôle** : Compaction Contextuelle Automatique In-Place sur Seuil (v5.231.38.1).
- **Sémantique** : Filtre Inlet exécuté à la priorité 25 (après `user_native_context_filter` à 20, et avant `new_context_filter` à 30), configurable par l'utilisateur via l'interface Open WebUI (`self.toggle = True`, icône SVG `fold-vertical` et `UserValves.ENABLE_AUTO_COMPACTION = True` par défaut).
- **Algorithme Clé** : Évalue `promptTokenCount` face à la constante SSOT `COMPACTION_TRIGGER_THRESHOLD_PCT` (`60%` de `ECHO_MAX_CONTEXT_SIZE` $\approx 629\,145$ tokens). Lorsque le seuil est franchi (hors sous-tours d'outils `role == "tool"`), affiche un HUD de progression (`#echo-compact-hud`) et délègue à `EchoCompactionEngine.execute_compaction` (`echo_core.py`) la compression vers l'enveloppe cible SSOT `COMPACTION_TARGET_CONTEXT_PCT` (`20%` $\approx 209\,715$ tokens) répartie via `get_compaction_shares(COMPACTION_COMPRESSED_SHARE_PCT)` en `63%` de contexte compressé `HEAD` ($\approx 132\,120$ tokens budget, plafonné à `maxOutputTokens = 65535`) et `37%` (`1 - COMPACTION_COMPRESSED_SHARE_PCT`) de tours récents gardés intacts `TAIL` ($\approx 77\,594$ tokens), sans troncature des messages ni retrait des balises `<artifact id="AEC_...">`.

### `tcp_keepalive_filter.py` (Inlet - Priorité 1)
**Rôle** : Maintien du pool de connexions HTTP/TCP Keep-Alive (v5.226.18.0).
- **Sémantique** : Filtre Inlet injectant un `setInterval` JavaScript (`fetch('/health', { method: 'HEAD', cache: 'no-store', keepalive: true })` toutes les 120s) afin de maintenir actif le pool de connexions HTTP/TCP Keep-Alive du navigateur face aux timeouts des proxys inverses et du WAF BunkerWeb (`proxy_read_timeout`).

### `window_manager_filter.py` (Inlet / Outlet - Priorité 2)
**Rôle** : Amorçage et Synchronisation du Gestionnaire de Fenêtres Agnostique (v5.231.11.1).
- **Sémantique** : Filtre bidirectionnel positionné à la priorité 2, immédiatement après `tcp_keepalive_filter.py` (priorité 1) et avant `edge_embed_bridge_filter.py` (priorité 3, qui bloque le pipeline Inlet pendant l'initialisation WebGPU).
- **Algorithme Clé** : En Inlet, garantit l'enregistrement idempotent des routes FastAPI `/echo/v1/wm/*` et `/static/loader.js` (`Cache-Control: no-store`) via `register_echo_wm_routes()`, puis injecte inconditionnellement à chaud (`Hot-Update` via `__event_emitter__`, idempotent en 0ms côté client) le runtime global `window.EchoWM` ainsi que `EchoUI.get_hud_geometry_js()` et `EchoUI.get_hud_rpc_bridge_js()`. En Outlet, synchronise la visibilité DOM des fenêtres (`EchoWM.syncAllWindowsVisibility()`).

### `user_native_context_filter.py` (Inlet - Priorité 20)
**Rôle** : Grounding Utilisateur & Préférences Contextuelles (v5.231.11.1).
- **Sémantique** : Injecte silencieusement dans `body["metadata"]` les préférences de partage du nom (`ENABLE_USER_NAME`) et la surcharge de localisation (`OVERRIDE_LOCATION`).

### `codex_links_filter.py` (Inlet / Outlet - Priorité 40)
**Rôle** : Navigation Interactive & Protocole URN Codex (v5.231.39.1).
- **Sémantique** : Filtre bidirectionnel s'exécutant à la priorité 40 (en Inlet immédiatement après `new_context_filter` à 30, et en Outlet avant `conversation_rag_filter` à 100), s'appuyant sur les constantes SSOT de `echo_constants.py` (`CODEX_URN_PATTERN`, `CODEX_ANCHOR_PATTERN`, `CODEX_HUD_ID`, `CODEX_ACTION_ID`, `OWUI_ORCHESTRATOR_MODEL`) et les fonctions factorisées de `echo_paths.py` (`normalize_codex_rel_path`, `check_codex_file_exists`).
- **Algorithme Clé** :
  - **Inlet & Outlet (Double injection Hot-Update & Bijection Suture)** : Injecte silencieusement en Inlet et Outlet le pont JS côté client (`EchoCodexUI.get_codex_bridge_js()` v5.231.39.1) via `EchoEvents.emit_execute`. Met à jour à chaud (`Hot-Update` non bloqué par `window._echoCodexBridgeAttached`, qui ne protège que `document.addEventListener`) la fonction globale `window.echoOpenCodex(chatId, ws, path)` et le handler `window._echoCodexClickHandler`, ainsi que le style `#echo-codex-links-style` (`a[href*="#codex:"] { text-decoration-skip-ink: none !important; cursor: pointer; }` empêchant la coupure visuelle du soulignement sur les virgules `,` et underscores `_`). `window.echoOpenCodex` vérifie strictement que `#echo-codex-hud` appartient au chat hôte courant et n'est pas parqué (`elCid === hostChatId && !isParked`) avant d'utiliser le Mode Chaud (`window.sendCodexAction({ action: 'switch_chat', ... })` + `_echoGeoCtrl.toggleMinimize()`), et déclenche en Mode Froid un appel REST direct (`POST /api/chat/actions/echo_codex_action`) avec `target_chat_id`, `workspace`, `target_file` et un `session_id` Socket.IO authentique (sans injecter `EchoWM.clientId`). En Inlet, restaure bijectivement les ancres `[✏️/👁️ label](#codex:target_chat:ws:path)` vers leur URN canonique `[label](codex:scope:ws/path)` (avec décodage URL via `normalize_codex_rel_path`) dans l'historique (`content` et `output`) pour préserver l'invariant de Suture de `echo_orchestrator.py`.
  - **Outlet** : Sanctuarise les blocs de code multilignes (` ```...``` `) via `_transform_outside_code_fences` et mute conjointement `last_msg["content"]` (`str`/`list`) **et** `last_msg["output"]` (`OutputItem[]` natif Open WebUI via `_mutate_message_texts`). Valide physiquement l'existence du fichier via `check_codex_file_exists` (`echo_paths.py`), garantissant une compatibilité totale avec la `sandbox` (sans forcer de dépôt Git ni créer de `.git`) en O(1) sans empreinte RAM : si le fichier existe, l'URN est mutée en ancre navigable `[✏️ label](#codex:chat_id:workspace:encoded_path)` (ou `[👁️ label]` si multi-chat, avec encodage `quote(clean_path, safe="/-_.")` préservant l'intégrité Markdown sur les espaces, virgules, parenthèses et apostrophes) ; si le fichier est absent ou fictif (anti-hallucination), le lien est neutralisé au profit du texte brut seul.

## 3. Dépendances Logiques
- Ces filtres interagissent nativement avec le moteur de base de données Qdrant et SQLite.
- Ils manipulent la structure `body` de l'API Open WebUI (FastAPI) et sont chargés de manière asynchrone par l'application.
