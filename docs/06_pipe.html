6. Le Pipe (Cortex Moteur & Suture Sémantique)

💡 Le Concept en 1 minute

Le Pipe est le Cortex Cérébral d'ECHO. C'est lui qui fait tout le travail de réflexion : il rassemble les souvenirs du passé, injecte les fichiers préparés par le Filtre, et discute avec les modèles Gemini. Sa spécialité est la "Suture" : il recoud les morceaux d'une conversation pour que l'IA ait l'impression de n'avoir jamais quitté la discussion, même si le système a redémarré entre-temps.

Le pipe_engine.py (v180.2) est l'unité centrale de traitement d'ECHO. Il n'est pas un simple connecteur API, mais un véritable Orchestrateur de Contexte capable de maintenir une cohérence absolue (Bit-Perfect) sur des sessions dépassant le million de tokens.

Philosophie Directrice : Le Pipe considère chaque tour de parole comme une opération chirurgicale. Il refuse la volatilité d'Open WebUI et s'appuie exclusivement sur son propre registre d'ombres (Shadows) pour garantir que l'IA ne souffre jamais d'amnésie ou de dérive logique.

L'Algorithme de Suture Sémantique

La fonction prepare_context est le cœur battant du système. Elle reconstruit l'historique Gemini en suivant une hiérarchie de restauration stricte :

⚙️ Restauration Bit-Perfect (Shadows)

Pour chaque message de l'historique, le Pipe vérifie la présence d'une "Ombre" dans la table SQLite message_shadows. Cette ombre contient la structure parts exacte telle qu'elle a été envoyée au modèle lors du tour original.

  • Verrou de Version (Anti-Ghosting) : La restauration n'est validée que si le couple (message_id, updated_at) correspond exactement. Si un utilisateur modifie un message, l'empreinte temporelle change, invalidant l'ombre et forçant une suture fraîche.
  • Intégrité Multimodale : ECHO scelle les inlineData (Base64) ou les ancres de fichiers, garantissant une persistance totale.

Intégration du Draft (Injection de Conscience)

Pour le message utilisateur courant, le Pipe récupère le Draft sémantique préparé par le Filtre (_echo_user_parts_draft). Ce draft est fusionné dynamiquement avec le texte brut de l'utilisateur.

Normalisation & Résolution de Placeholders

L'unité _ensure_gemini_parts assure la conformité stricte avec l'API Google. C'est ici que s'opère la Résolution Dynamique des Identités :

  • ##ECHO_VERSION## : Injecte la version exacte du framework.
  • ##MODEL_ID## : Résout l'identité du modèle actif (ex: MODEL_PRO).
  • ##MODEL_ORIGIN## : Identifie le modèle ayant initié le tour.

La Cascade Cognitive (Fluctuation Continue)

ECHO introduit le concept de Routage Dynamique Inter-Modèle. En mode AUTO, le Pipe gère une boucle de récursion intelligente.

flowchart TD A[Démarrage : MODEL_LITE] --> B{Analyse Contextuelle} B -->|Tokens < 25%| C[Maintenir LITE/FLASH] B -->|Tokens 25-50%| D[Escalade vers FLASH/PRO] B -->|Tokens > 50%| E[Escalade PRO Impérative] D & E --> F[Génération Plan de Transfert] F --> G[Injection dans Nouveau Modèle]

L'Outil de Transfert : changement_niveau_cognitif

Injecté dynamiquement, il permet à un modèle de se déclarer incompétent ou d'anticiper une surcharge contextuelle.

  • Plan de Transfert : Le modèle sortant rédige un plan Markdown pour son successeur.
  • Mutation Chirurgicale : Le Pipe intercepte cet appel, modifie l'identité du modèle et relance la requête.

Gestion Chirurgicale des Pensées (CoT)

ECHO ne conserve JAMAIS le texte brut de la pensée dans l'historique des tours suivants. À la place, il utilise la thoughtSignature :

  • L'Ancre Google : La thoughtSignature est une ancre logique (KV Cache) fournie par Google. En la réinjectant, ECHO permet au modèle de "retrouver ses esprits" sans avoir à relire ses propres pensées.
  • Économie Massive : Ce protocole réduit la charge contextuelle de 30% à 70%.

Sécurité & Résilience API

  • Multi-Clés & Rotation : Bascule automatique de clé après KEY_SWITCH_THRESHOLD échecs.
  • HTTP/2 Strict : ECHO impose le protocole HTTP/2 pour réduire la latence.

Phase de Scellement (Le Verrouillage)

  1. Shadow Sealing : Enregistrement dans message_shadows.
  2. Cognitive Sealing : Ancrage de la thoughtSignature et du tool_journal.
  3. File Registry Update : Les fichiers sont marqués comme processed et déplacés vers le Vault.
  4. HUD Refresh : Mise à jour de la Context Gauge.

✅ Audit de Vérité (v180.2)

Le StreamProcessor de la version 180.2 a été optimisé pour le multiplexage HTTP/2. Il est capable de traiter en parallèle les balises de pensée et les appels d'outils, permettant une réactivité accrue lors des phases d'orchestration complexe.
