3. Les Librairies Partagées (echo_libs)

Au cœur du système déployé opèrent les librairies partagées, véritables moteurs des fonctionnalités techniques d'ECHO.

💡 Que sont les ECHO Libs ?

Les ECHO Libs sont un ensemble de fonctions de base consolidées, centralisées et réutilisables par tous les modules du framework (Filtres, Pipe, Actions, Admin). Elles évitent la duplication de code et garantissent que chaque composant parle la même langue technique.

Le socle technique d'ECHO repose sur un triptyque de librairies situées dans 14-owui-libs/. Ces modules assurent la cohérence, la résilience et l'interoperabilité de tout l'écosystème.

echo_constants.py : Constantes & Topologie (v2.7)

Le registre unique des vérités du système : IDs de modèles, chemins de répertoires, timeouts et limites de contextes.

ConstanteValeur / Rôle
ECHO_USERS_ROOT/app/backend/data/users (Stockage des BDD et Vaults)
ECHO_UPLOADS_DIR/app/backend/data/uploads (Transit des fichiers OWUI)
ECHO_USER_AGENTgemini-cli/0.42.0 (Identité réseau)

Détection MIME Intelligente

La fonction get_gemini_mime utilise une cascade de 6 niveaux : Mapping ECHO, Mimetypes Std, Magic Numbers, Whitelist Gemini, Null-Byte Sniffing (Text-Sniffing), et Fallback.

echo_auth.py : Validation d'Identité

Gestionnaire d'identité souveraine. Le AuthService gère l'enrôlement des clés API. Il valide en parallèle (asyncio.gather) les clés auprès de Google avant de les sceller dans identity.db.

echo_utils.py : Le Cœur Réactif (v3.8)

⚙️ EchoStateManager : L'Architecture Bit-Perfect

Le state_manager est l'organe de mémoire persistante. Il utilise un double hachage SHA-256 pour garantir l'intégrité :

  • Invariant Hash : SHA-256 du triplet (rôle, contenu, tool_io).
  • Cumulative Hash : SHA-256 de (invariant + parent_cumulative).
  • Table message_shadows : Stockage du JSON brut original (Shadowing) lié au timestamp updated_at physique.

⚙️ EchoGeminiClient : Résilience & Mesh d'Authentification

Moteur d'appel API avec support HTTP/2 Strict et architecture symétrique (AI Studio & Google Cloud Code Assist). Il orchestre un "Mesh" d'identifiants (Clés API, OAuth2) pour une autonomie maximale et permet la capture asynchrone des ThoughtSignatures via les flux SSE.

  • Failover Hybride :
    • Erreurs de Flux (429, 500, 503) : Bascule automatique après KEY_SWITCH_THRESHOLD échecs avec Backoff exponentiel.
    • Erreurs de Droits (403, 404) : Bascule immédiate vers la source suivante si le modèle (ex: PRO) n'est pas autorisé sur l'identifiant actuel.
  • Transparence Totale : Notification en temps réel via events.status lors des périodes de réessai (Retries) et des basculements de mesh, éliminant l'impression de gel de l'interface en mode Streaming.
  • Support OAuth2 : Rafraîchissement proactif et silencieux des jetons Bearer (cycle de 50 min) pour les comptes Google Cloud.

EchoEvents, EchoUI & VisualEngine

  • EchoEvents : Bus d'événements asynchrone (status, toast, call). Permet de pousser des messages de statut de manière uniforme.
  • EchoUI : Moteur HUD. Gère le Monitor, la Context Gauge et le Web Replay. (Déplacé dans echo_ui.py).
  • VisualEngine : Registre universel des moteurs visuels (Markmap, Mermaid, ECharts, Vega, etc.). (Nouveau : echo_visuals.py).

Protocoles Sémantiques

  • split_thought_process : Isolation des balises <think> pour l'archivage CoT.
  • wrap_tool_output : Contrat de sortie multipart (Text, Thoughts, Media, New Files).

⚙️ Précision Mécanique : Résilience des Données

Le EchoStateManager garantit la persistance des ombres même en cas de crash brutal du conteneur grâce au mode WAL (Write-Ahead Logging) de SQLite. Cette configuration permet des écritures concurrentes rapides sans risque de corruption de la base de données.
