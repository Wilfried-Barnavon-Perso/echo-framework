9. Admin Manager (Console de Régulation)

Afin de garder un contrôle absolu sur le Kernel et l'ensemble des modules conteneurisés, l'Admin Manager offre une surface de supervision complète.

Fiche d'Identité Technique

📊 Admin Manager

Nature : Micro-service de régulation et monitoring (Flask API).

Source : 20-docker-admin-manager/server.py (v2.6)

Rôle : Assurer la santé du cluster ECHO, gérer les sauvegardes à chaud, orchestrer l'oubli organique de la mémoire Qdrant et fournir une interface de sécurité (rotation des mots de passe).

Exécutant : Conteneur Docker echo-admin-manager tournant sous Python 3.11.

Interconnexions :

  • Docker : Commande le Docker Daemon via /var/run/docker.sock.
  • Stockage : Accès direct au volume /app/backend/data/users/ pour les backups.
  • Mémoire : Requête l'API Qdrant pour la maintenance des vecteurs.

💡 À quoi sert la Console Admin ?

Si ECHO est un organisme vivant, l'Admin Manager est son système immunitaire et métabolique. Il surveille que tout fonctionne bien, fait le ménage dans les vieux souvenirs inutiles (Élagage), et crée des copies de sécurité pour que vous puissiez restaurer votre IA en cas de problème technique. C'est l'outil de l'administrateur système pour garantir la pérennité de la citadelle.

Le module server.py agit comme le poste de pilotage infrastructure d'ECHO. Il assure l'interopérabilité entre les couches logicielles et l'orchestration Docker.

1. Monitoring Holistique

L'interface affiche en temps réel les constantes vitales de l'infrastructure :

  • Sessions Actives : Compteur réel basé sur les fichiers .db présents dans les répertoires /chats/ du Vault.
  • Volume Vault : Taille totale occupée par les documents, les bases SQLite et les identités.
  • Santé Docker : État (Up/Down) de chaque conteneur de la stack ECHO, avec possibilité de redémarrage forcé.

2. Cycle de Vie & Oubli Organique

L'Admin Manager centralise la logique d'Atrophie Sémantique pour alléger le traitement en temps réel des filtres :

  • Sync Qdrant : Élimination automatique des points vectoriels orphelins (liés à des utilisateurs ou chats supprimés dans OWUI).
  • TTL Decay : Application des durées de rétention (30 à 540 jours) selon l'importance du souvenir. Les souvenirs périmés sont définitivement purgés de la base vectorielle.
  • Vacuum SQLite : Optimisation physique régulière des bases de données de session (commande VACUUM) pour maintenir les performances d'accès.

3. Sauvegardes & Restauration à Chaud

Le module de backup garantit une reprise d'activité après sinistre :

  • Procédure : Arrêt temporaire du conteneur Core, compression atomique (tar.gz) de l'infrastructure de données, et redémarrage immédiat.
  • Rotation : Nettoyage automatique des anciennes archives selon un nombre limite ou un âge maximum.

4. Surface de Sécurité

La console offre des leviers de contrôle direct sur l'identité :

  • Reset Auth : Purge instantanée de tous les tokens Google enregistrés dans les fichiers identity.db du Vault.
  • Passwd Rotation : Modification du mot de passe de l'hôte système via un pont SSH sécurisé utilisant paramiko.
  • Secret Maître : L'API /api/admin/password permet la récupération sécurisée du mot de passe administrateur généré lors du bootstrap.

⚙️ Précision Mécanique : L'Isolation Privilégiée

Bien que l'Admin Manager ait accès au Docker Daemon, il n'est jamais exposé directement au WAN par défaut. Son accès est filtré par BunkerWeb et nécessite une authentification forte. En cas de déploiement local pur, il n'est accessible que via le réseau bridge interne ou le proxy inverse sécurisé.
