7. L'Arsenal des Outils (Sovereign Toolbox)

L'intelligence du Pipe serait théorique sans moyens d'action. L'Arsenal des Outils fournit les capacités d'interaction et d'analyse requises.

Fiche d'Identité Technique

🛠️ L'Arsenal (Outils d'Action)

Nature : Écosystème de Micro-services conteneurisés et d'API REST (Tool Calling).

Source : Dossiers 12-owui-tools/ (Définition API) et 20-docker-*/ (Moteurs d'exécution).

Rôle : Fournir au Pipe les capacités exécutives pour interagir avec l'extérieur (Navigation Web, Exécution de code Python, Gestion de fichiers) tout en maintenant l'isolation sécuritaire.

Exécutant : Le Pipe (Open WebUI) déclenche la requête HTTP, qui est ensuite exécutée par les conteneurs Docker spécialisés (Sandbox).

Interconnexions :

  • Input : Reçoit les arguments JSON générés par l'API Gemini (Tool Call).
  • Action locale : Exécute des scripts, lit/écrit dans le Vault (système de fichiers local).
  • Action réseau : Navigue sur le WAN (Headless Browser) ou requête le proxy SearxNG.
  • Output : Retourne le résultat structuré (JSON multipart) au Pipe.

💡 Comprendre l'Arsenal

Une IA standard est "enfermée" dans une boîte de texte. L'Arsenal agit comme les "mains" et les "outils" d'ECHO. Lorsque le cerveau (le Pipe) réalise qu'il ne sait pas quelque chose (ex: la météo du jour, ou comment trier un fichier Excel complexe), il rédige une consigne précise et la transmet à l'un des outils de l'Arsenal. Ce dernier exécute la tâche de manière sécurisée et renvoie le résultat au cerveau.

L'Arsenal ECHO n'est pas une simple collection de fonctions, mais un écosystème d'outils souverains conçus pour l'autonomie cognitive. Chaque outil respecte un protocole de communication multimodal strict et interagit directement avec le Vault utilisateur.

Principes Directeurs

  • Souveraineté : Les données ne quittent jamais l'infrastructure ECHO sauf pour les appels API chiffrés.
  • Multimodalité native : Capacité à renvoyer du texte, des pensées, des médias et des artefacts dans un seul flux.
  • Traçabilité : Chaque appel d'outil est journalisé dans la table tool_journal.

Le Protocole Multipart (wrap_tool_output)

Pour dépasser les limites des réponses textuelles, ECHO utilise un format JSON structuré encapsulant plusieurs types de données.

Composants du Multipart

Type Description Traitement par le Pipe
text La réponse textuelle principale de l'outil. Injecté comme functionResponse.
thought Raisonnement interne de l'outil ou du sous-modèle. Isolé pour afficher la Chain-of-Thought sans polluer la sortie finale. Ces données seront ensuite réinjectées dans le contexte à travers la Suture lors du tour suivant.
media Binaire (Base64) avec MIME type (Image, PDF, HTML). Converti en inlineData Gemini.
nouveaux_fichiers Métadonnées des fichiers créés ou téléchargés. Injecté via le protocole "Suture" pour assurer la rémanence.

Le Système "Vault" (Coffre-Fort)

Le Vault est l'espace de stockage persistant et isolé de chaque utilisateur (/app/backend/data/users/{user_id}/files/).

  • Indexation : Chaque fichier possède un file_id unique au format U_{uid}_C_{cid}_T_{ts}.
  • Persistance : Les outils scellent automatiquement les artefacts (captures d'écran, logs) dans le Vault.
