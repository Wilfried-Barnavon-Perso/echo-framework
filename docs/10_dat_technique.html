2. Gestion Spécifique de Gemini (Implicit Caching)

L'algorithme garantit la mobilisation du cache de Google par la stabilité du préfixe.

  • Bien que etat_echo contienne une horodate au moment de la génération, ECHO stocke la version textuelle exacte du message envoyé au tour N.
  • Au tour N+1, il ne recalcule pas l'heure du tour N, il renvoie le bloc exact stocké (l'ombre riche).
  • Le flux envoyé à Google reste donc identique bit-à-bit d'une requête à l'autre, permettant à Google de réutiliser le contexte déjà traité à 100%.

3. Authentification et Bypass PKCE

ECHO détourne l'endpoint cloudcode-pa.googleapis.com (Cloud Code) pour utiliser les capacités Google One / AI Pro de manière souveraine.

  1. PKCE (Proof Key for Code Exchange) : ECHO génère un code_verifier (secret) et un code_challenge (S256).
  2. Interception : Le code retourné via l'URL d'autorisation Google (4/...) est intercepté par le filtre.
  3. Échange : Le pipe_engine échange le code + le verifier contre un access_token et un refresh_token, qu'il sauvegarde de manière chiffrée.

4. Topologie Docker (Orchestration)

L'infrastructure est orchestrée via stack-echo.yml (et bunkerweb-stack.yml en mode Edge).

  • echo-network : Réseau bridge interne isolé.
  • echo-webui-core : Interface utilisateur (Point d'entrée principal sur le port 3000).
  • echo-admin-manager : Micro-service de maintenance et d'administration (Port 3001).
  • echo-python-worker : Conteneur isolé (Flask + Multiprocessing) pour l'exécution du code python_code_executor.py.
  • echo-browser-agent : Conteneur isolé (Playwright) pour le navigation_engine_tool.py.
