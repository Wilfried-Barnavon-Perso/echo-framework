5. Les Filtres (Conscience & Mémoire)

En provenance de l'interface utilisateur, chaque requête transite par une couche de filtrage double qui prépare le contexte et gère la base vectorielle des souvenirs.

💡 Pourquoi deux filtres ?

ECHO utilise deux filtres spécialisés pour gérer son flux :

  • Le Filtre de Conscience (Inlet/Outlet) : Il préanalyse les données entrantes pour éviter de surcharger le cerveau central.
  • Le Filtre de Mémoire (Outlet) : Il s'occupe de ranger les informations importantes dans le registre vectoriel (Qdrant) après chaque réponse.

1. Le Filtre de Conscience (new_context_filter.py v7.0)

🌐— Filtre New Context

Nature : Middleware d'interception Inlet/Outlet haute résilience.

Source : 11-owui-filters/new_context_filter.py

Rôle : Gateway Cognitive. En phase Inlet, il effectue le "Smart Context" : il résume les fichiers massifs via Gemini Flash pour que le Pipe reçoive un dictionnaire exploitable sans saturer son contexte, tout en assurant une résilience totale face aux erreurs de parsing.

Exécutant : Processus Python d'Open WebUI.

Connexions : Alimente le Pipe (via les métadonnées environnement_contexte).

2. Le Filtre de Mémoire (conversation_memory_filter.py)

🧠 Filtre Memory

Nature : Middleware d'interception Outlet (Post-génération).

Source : 11-owui-filters/conversation_memory_filter.py

Rôle : Gestionnaire de la Base vectorielle des souvenirs. Il distille les échanges, génère des vecteurs et les stocke dans Qdrant avec un système de TTL (Time To Live).

Exécutant : Processus Python d'Open WebUI.

Connexions : Envoie les souvenirs vers Qdrant.

⚙️ Précision Mécanique : L'Aiguillage Inlet

Le new_context_filter utilise la valve MAX_DIRECT_TEXT_SIZE (256 Ko par défaut). Si un fichier dépasse ce seuil, il est automatiquement routé vers l'unité de distillation (Gemini Flash). Cela garantit que le modèle principal (Gemini Pro) reçoit une synthèse structurée plutôt que des milliers de lignes de données brutes, préservant ainsi sa capacité de raisonnement critique.

Le Manifeste de Vérité : environnement_contexte

Le bloc YAML injecté au sommet du Draft est le pivot de la coordination cognitive. Il contient les placeholders ##MODEL_ID## et ##MODEL_ORIGIN##, qui seront résolus dynamiquement par le Pipe.

Structure du bloc environnement_contexte (Injecté par le Filtre)
version_framework_echo: "##ECHO_VERSION##"
modèle_actuel: "##MODEL_ID##"
modèle_origine: "##MODEL_ORIGIN##"
nom_utilisateur: "..."
date_et_heure: "2026-04-03 12:00"
localisation: "Paris, France"
timezone: "Europe/Paris"
registre_fichiers:
  source.py:
    id: "F1"
    mime: "text/plain"
    statut: "transmitted"

Smart Memory : La Conscience Persistante

Le conversation_memory_filter.py (v3.1) gère la mémoire à long terme d'ECHO en phase Outlet.

  • Distillation : Si le seuil minimal de messages est atteint, une tâche asynchrone est lancée pour résumer la conversation.
  • Vectorisation : Le résumé est transformé en vecteurs par Gemini Embedding-2.
  • Stockage Qdrant : Le "souvenir sémantique" est ancré dans la collection echo_memory.

Sécurité Outlet : Masquage Chirurgical

En phase Outlet (post-génération), le filtre applique un balayage final via Regex pour s'assurer qu'aucune clé API ne "fuit" dans l'interface visuelle. Toute clé détectée est remplacée par : [CLÉ API GOOGLE MASQUÉE PAR SÉCURITÉ].

✅ Le point sur l'exactitude (v7.0)

Le Filtre implémente un système de Dédoublonnage d'Accès : avant d'envoyer un fichier volumineux au Pipe, il vérifie s'il provient déjà du dossier local de l'utilisateur (Vault). Si le fichier est déjà présent dans l'Espace Personnel, il ne transmet que la référence, économisant ainsi de la bande passante et des ressources de stockage temporaires.
