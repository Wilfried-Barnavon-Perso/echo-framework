5. Le Filtre (Conscience Périphérique)

💡 Le Concept en 1 minute

Le Filtre est le Secrétaire Particulier d'ECHO. Avant que l'IA ne lise votre message, le Filtre l'intercepte pour faire le tri : il résume les gros fichiers, vérifie vos clés de sécurité, et prépare un dossier complet (le Draft) pour le cerveau central (le Pipe). C'est lui qui s'assure que l'IA ne soit pas submergée par trop d'informations d'un coup.

Le new_context_filter.py (v6.63) constitue la Gateway Cognitive d'ECHO. Positionné en amont du Pipe, il intercepte, analyse et transmute chaque signal entrant en un "Draft" sémantique haute fidélité. Sa mission est de préparer un terrain bit-perfect pour la suture neuronale.

Contrôle Souverain : ECHO définit self.file_handler = True. Ce réglage critique désactive l'unité de Retrieval (RAG) native d'Open WebUI, transférant l'intégralité de la gestion documentaire à la logique propriétaire d'ECHO.

Smart Context 3.0 : L'Aiguillage Multimodal

ECHO n'injecte pas les fichiers aveuglément. Il pratique une analyse granulaire pilotée par la fonction _process_file_task, capable de traiter les fichiers en parallèle avec un contrôle de flux strict.

1. L'Algorithme de Décision (Quadruple Flux)

Chaque fichier subit une évaluation basée sur son type MIME et sa taille réelle (Valve MAX_DIRECT_TEXT_SIZE fixée à 256 Ko).

Flux Conditions Action ECHO
Binaire Direct Image/Audio/Vidéo/PDF < 256 Ko Encapsulation Base64 (inlineData) native.
Injection Texte Texte/Code < 256 Ko Insertion brute dans un bloc Markdown Code.
Smart Context Document Volumineux (> 256 Ko) Distillation via Gemini Flash (Résumé technique).
Indexation Format non supporté par Gemini Marquage simple dans le registre (Fallback).

⚙️ Moteur de Sniffing MIME (ECHO-Logic)

Le protocole get_gemini_mime assure une identification robuste là où les systèmes standards échouent :

  • Phase 1 : Mappings ECHO : Reconnaissance immédiate des formats de développement (.py, .sh, .ts, etc.).
  • Phase 2 : Magic Number Sniffing : Analyse de la signature binaire via filetype pour les fichiers sans extension.
  • Phase 3 : Null-Byte Sniffing : Si aucun caractère nul (\x00) n'est détecté dans les 1024 premiers octets, le fichier est forcé en text/plain, autorisant l'IA à analyser du code source exotique.

Moulage Sémantique (Smart Context)

Pour les documents massifs, le Filtre invoque Gemini Flash de manière autonome avec une systemInstruction chirurgicale : "Tu es l'unité de prétraitement contextuel d'ECHO. Produire un résumé technique exhaustif, identifier la structure, le but et les points clefs." Le résultat est injecté dans le Draft avec le statut summarized.

Authentification Stealth : Le Coffre-Fort Temporaire

Le filtre assure la sécurité des identifiants sans jamais les exposer à l'interface utilisateur.

  • Interception : Le filtre surveille l'état ECHO_SESSION_AUTH_PENDING. Toute chaîne capturée par GOOGLE_API_KEY_REGEX est extraite du message.

Architecture du Draft & Cycle de Vie

Contrairement aux filtres standards, ECHO ne modifie pas directement le contenu du message en phase Inlet. Il construit un Draft complexe dans les métadonnées (_echo_user_parts_draft).

flowchart LR A[Utilisateur] --> B[Filtre Inlet] B --> C{Analyse Multimodale} C -->|Images/PDF| D[Base64 Inline] C -->|Gros Fichiers| E[Résumé Flash] C -->|Texte/Code| F[Bloc Markdown] D & E & F --> G[Draft Sémantique] G --> H[Pipe Outlet]

Le Manifeste de Vérité : etat_echo

Le bloc JSON injecté au sommet du Draft est le pivot de la coordination cognitive. Il contient les placeholders ##MODEL_ID## et ##MODEL_ORIGIN##, qui seront résolus dynamiquement par le Pipe.

Smart Memory : La Conscience Persistante

Le conversation_memory_filter.py (v2.3) gère la mémoire à long terme d'ECHO en phase Outlet.

  • Distillation : Si le seuil minimal de messages est atteint, une tâche asynchrone est lancée pour résumer la conversation.
  • Vectorisation : Le résumé est transformé en vecteurs par Gemini Embedding-2.
  • Stockage Qdrant : Le "souvenir sémantique" est ancré dans la collection echo_memory.

Sécurité Outlet : Masquage Chirurgical

En phase Outlet (post-génération), le filtre applique un balayage final via Regex pour s'assurer qu'aucune clé API ne "fuit" dans l'interface visuelle. Toute clé détectée est remplacée par : [CLÉ API GOOGLE MASQUÉE PAR SÉCURITÉ].

✅ Audit de Vérité (v6.63)

Le Filtre implémente un système de Dédoublonnage Invariant : avant d'envoyer un fichier volumineux au Pipe, il calcule son hash. Si le fichier est déjà présent dans le Vault, il ne transmet que la référence, économisant ainsi de la bande passante et des ressources de stockage temporaires.
