15. Déploiement & Infra

Installer et maintenir votre instance souveraine selon votre environnement

ECHO v6 propose trois voies d'installation automatisées — sur machine virtuelle Windows (Hyper-V), sur serveur ou poste Linux natif, ou directement sous Windows via WSL2 — suivies d'un jeu unifié de commandes d'administration pour superviser, exposer en HTTPS et mettre à jour votre plateforme.

1. Choisir votre voie d'installation

Avant de lancer l'installation, identifiez le mode le mieux adapté à votre machine et à votre usage. Chaque scénario prépare l'environnement requis, vérifie l'espace disque et la mémoire disponibles, puis démarre automatiquement l'ensemble des services ECHO.

Voie A — Hyper-V (Windows 11 Pro)

Crée une machine virtuelle Ubuntu dédiée et isolée de votre poste Windows. Recommandée si vous souhaitez une séparation stricte entre votre bureau Windows et le serveur ECHO, avec réseau interne dédié.

Voie B — Linux Natif (Ubuntu / Debian)

Installe ECHO directement sur un serveur, un mini-PC ou une station Ubuntu ou Debian, sans surcouche de virtualisation. Recommandée pour un serveur permanent ou une exposition sur nom de domaine public.

Voie C — WSL2 (Windows 10 / 11)

Déploie ECHO dans votre sous-système Linux sous Windows sans dépendre de Docker Desktop. Recommandée pour un usage personnel ou développeur directement depuis votre poste Windows.

2. Lancer l'installation pas à pas

Voie A — Machine virtuelle Hyper-V (Windows 11 Pro)

Ouvrez un terminal PowerShell en tant qu'Administrateur à la racine du dépôt ECHO, assurez-vous que l'image ISO Ubuntu Server est présente à l'emplacement configuré dans le script, puis exécutez l'assistant :

PowerShell (Administrateur) — Déploiement Hyper-V
.\install-hyperv.ps1

Le script configure automatiquement le réseau interne, crée la machine virtuelle (8 Go de mémoire vive, 4 cœurs virtuels, disque de 60 Go), injecte le code source et déclenche l'installation complète au premier démarrage.

Voie B — Linux natif (Ubuntu / Debian)

Sur une machine Ubuntu ou Debian fraîchement installée (au moins 10 Go d'espace disque libre, 20 Go recommandés, et 8 Go de mémoire vive recommandés), lancez une seule commande en tant que super-utilisateur :

Terminal Linux — Installation directe
curl -fsSL https://raw.githubusercontent.com/Wilfried-Barnavon-Perso/echo-framework/main/install-linux.sh | sudo bash

Pour déployer une branche de développement spécifique, utilisez le paramètre --branch dev :

Terminal Linux — Installation sur la branche dev
sudo bash <(curl -fsSL https://raw.githubusercontent.com/Wilfried-Barnavon-Perso/echo-framework/main/install-linux.sh) --branch dev

Voie C — WSL2 sous Windows (Ubuntu 22.04+ / Debian)

Dans votre terminal Ubuntu sous WSL2, lancez l'installateur dédié :

Terminal WSL2 — Installation directe
curl -fsSL https://raw.githubusercontent.com/Wilfried-Barnavon-Perso/echo-framework/main/install-wsl2.sh | sudo bash

Attention si Docker Desktop est installé sur Windows

La voie WSL2 installe un moteur autonome directement dans Linux et refuse de s'exécuter sur une distribution où l'intégration Docker Desktop est activée. Désactivez cette intégration pour la distribution choisie (ou utilisez une distribution Ubuntu dédiée) avant de lancer install-wsl2.sh.

Récupérer vos identifiants initiaux

Une fois le déploiement terminé, exécutez echo-show-admin dans le terminal de la machine cible pour afficher l'adresse d'accès et le mot de passe administrateur généré automatiquement.

3. Exposer votre instance ou la garder privée

Par défaut, ECHO démarre en mode privé pour un accès direct depuis votre poste ou votre réseau local. Dès que vous disposez d'un nom de domaine pointant vers votre machine, vous pouvez activer en une commande la protection HTTPS automatique, le pare-feu applicatif et le portail de connexion sécurisé :

Terminal — Activer ou désactiver l'exposition publique sécurisée
sudo enable-bunkerweb
sudo disable-bunkerweb

L'activation déploie automatiquement les certificats TLS, la page de connexion centralisée (auth.<domaine>), l'espace personnel des utilisateurs (my.<domaine>) et l'interface principale (ui.<domaine>). La désactivation rétablit immédiatement l'accès local direct sans supprimer vos données.

4. Commandes d'exploitation au quotidien

L'installation rend disponibles des commandes globales accessibles depuis n'importe quel répertoire du terminal :

Commande Rôle pour l'opérateur Quand l'utiliser
echo-show-admin Affiche les adresses d'accès et les identifiants initiaux de l'instance. Juste après l'installation ou en cas d'oubli du mot de passe initial.
echo-ps Liste l'état de santé de tous les services en cours d'exécution. Pour vérifier qu'aucun composant n'est arrêté ou en erreur.
echo-logs Affiche les journaux en temps réel de la plateforme. Pour diagnostiquer un comportement inhabituel ou suivre un traitement.
echo-version Indique la version installée, la branche active et l'outil d'installation utilisé. Avant une mise à jour ou lors d'une vérification d'audit.
echo-update Récupère les mises à jour de code et recharge les services sans reconstruction lourde. Pour les correctifs rapides entre deux versions majeures.
echo-upgrade Met à niveau la plateforme complète (reconstruction et redémarrage ordonné). Lors d'un changement de version majeure ou d'interface.
echo-os-upgrade Met à jour le système Linux hôte en arrêtant proprement les bases de données au préalable. Pour la maintenance de sécurité mensuelle du système d'exploitation.
echo-clean Libère l'espace disque (images inutilisées, journaux anciens, caches système). Exécuté automatiquement chaque jour, ou manuellement avant une saturation disque.
echo-sync Synchronise un dépôt source modifié localement vers le dossier d'exécution système. Réservé aux opérateurs ou développeurs qui personnalisent les sources en local.

Reconstruction complète (echo-rebuild)

La commande de réinitialisation complète exige une double confirmation écrite explicite (CONFIRMER puis DETRUIRE) car elle efface les volumes de données et régénère les secrets de l'instance.

Dossier d'Ingénierie : Paramètres Hyper-V, Pré-vol Linux/WSL2, Cycle Compose & Scripts Ops

1. Voies de Provisioning (install-hyperv.ps1, install-linux.sh, install-wsl2.sh)

  • install-hyperv.ps1 (v6.18.12.1) : Crée de façon idempotente le commutateur interne ECHO-Internal, le NAT ECHO-NAT (sous-réseau 192.168.118.0/24, passerelle 192.168.118.254, IP statique VM 192.168.118.100/24, DNS [86.54.11.100, 1.1.1.1, 8.8.8.8]) et optionnellement les règles DNAT multi-VM safe ($ENABLE_DNAT = $false par défaut en phase interne). Provisionne une VM Ubuntu 26.04.1 (4 vCPU, RAM fixe à 3 niveaux 8192 Mo priorité 50, snapshots automatiques désactivés, VHDX dynamique 60 Go avec calibration Storage QoS hors cache en 2^N) via Cloud-Init et disque Seed CIDATA de 256 Mo embarquant l'archive ZIP filtrée par .gitignore (branche par défaut dev, hostname normalisé echo-v<majeure>-<branche>).
  • install-linux.sh (v6.18.16.1) : Supporte Ubuntu et Debian natifs (garde non-interactive si WSL2 détecté sans TTY). Contrôles pré-vol : RAM (avertissement si < 7500 Mo) et disque sur /opt (blocage si < 10 Go, avertissement si < 20 Go). Installe de façon non-destructive Docker CE / Compose V2 (ou complète docker.io sans couper le démon), yq v4.40.5 mappé dynamiquement selon dpkg --print-architecture, cron, rsync, psmisc, chrony, jq, et enregistre la traçabilité linux: dans echo_deploy_script_version.
  • install-wsl2.sh (v6.18.16.1) : Cible Ubuntu 22.04+ / Debian sous WSL2. Détecte et bloque l'intégration Docker Desktop scopée sur la distribution (_is_docker_desktop_integrated). Vérifie la mémoire totale RAM + Swap (avertissement RAM < 7500 Mo, seuil critique RAM + Swap < 6800 Mo orientant vers %UserProfile%\.wslconfig) et l'espace disque (10 Go / 20 Go). Installe Docker Engine natif dans la distro (hors PATH Windows) et enregistre la traçabilité wsl2:.

2. Cycle de Déploiement Compose (00-echo-scripts/install-stack.sh v6.18.15.1 & echo-globals.sh v6.18.15.1)

  • Orchestration factorisée : init_echo_compose_cmd(), build_echo_compose_args(), echo_compose(), has_active_echo_domain() et compute_echo_detected_origins() détectent Compose V2/V1 et assemblent 01-config/stack-echo.yml (et 01-config/bunkerweb-stack.yml si actif).
  • Pré-build isolé & Watchtower : Arrête gracieusement echo-watchtower (avec trap EXIT de reprise), purge les éventuels conteneurs Compose temporaires (^[0-9a-f]{12}_echo-) en état Created, compile l'image socle echo-python-base:latest (CMAKE_BUILD_PARALLEL_LEVEL=2, throttle 30 jours via .last_base_pull), puis pré-construit isolément echo-webui (allocation Node V8 --max-old-space-size=6144) avant de lancer le build parallèle borné (COMPOSE_PARALLEL_LIMIT=2).
  • Swap & Docker Autosafety : ensure_swap_and_vm_tuning() crée un /swapfile de 4 Go (avec chattr +C pour compatibilité Btrfs et persistance /etc/fstab, exempté sous WSL2) et fixe vm.swappiness=25. ensure_docker_autosafety() configure la rotation des logs Docker (max-size: 10m, max-file: 3) dans /etc/docker/daemon.json (avec restart_docker_daemon_and_wait()) et installe le lien /etc/cron.daily/echo-clean.
  • Secrets & Provisioning natif : ensure_echo_secrets() génère avec umask 077 les clés de /opt/ECHO/.env (BW_DB_PASSWORD, SEARXNG_SECRET, ECHO_SSO_SECRET, N8N_ENCRYPTION_KEY, ECHO_VAULT_ENCRYPTION_KEY, synchronisation .owui-admin-secret ↔ ECHO_ADMIN_PASSWORD). Le provisioning des plugins et du modèle maître est assuré au boot par open_webui.echo.bootstrap.
