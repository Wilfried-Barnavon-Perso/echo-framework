9l. Serveur MCP Broker

Serveur MCP Broker (Model Context Protocol)

Le MCP Broker est un composant stratégique (Tier 2) qui permet à l'agent ECHO de s'interfacer de manière standardisée avec des sources de données et outils externes. Agissant comme un Proxy HTTP complet (m5_proxy_mcp.py) en ASGI, il expose dynamiquement un schéma d'outils (JSON Schema) que le LLM peut consommer nativement.

Architecture Proxy & Sécurité

  • Délégation d'API : Le modèle n'appelle jamais directement les API externes. Il délègue cette tâche au MCP Broker via l'outil remote_mcp_tool.py. L'Identity Vault fusionne dynamiquement les schémas du Broker pour injecter les secrets requis avant l'exécution.
  • Forwarding Transparent d'Erreurs : Contrairement à une simple interception, le Broker capture les erreurs d'exécution des outils externes (ex: timeout API, erreur de validation) et les formate en JSON natif pour les remonter directement dans le contexte du LLM. Le modèle peut ainsi appliquer une correction autonome (auto-heal) de sa requête.
  • Middleware d'Authentification ASGI : La sécurité est assurée par une interception silencieuse de l'en-tête x-openwebui-user-id au niveau le plus bas du proxy, garantissant que chaque appel MCP est strictement isolé et authentifié.

Modules Actifs

  • Corporate (Sirene/Bodacc) : Outils de recherche de données d'entreprise.
  • Academic : Interfaçage avec des bases de connaissances scientifiques.
  • Omnisearch Jobs : Moteur de recherche d'offres d'emploi.

L'Identity Vault fusionne dynamiquement les schémas de ce Broker avec l'API locale N8N pour la distribution sécurisée des secrets.

Forwarding et Inter-Services

Le MCP Broker agit comme un Proxy HTTP complet avec un middleware ASGI. Il intercepte le header x-openwebui-user-id pour authentifier silencieusement les requêtes, et remonte les erreurs applicatives de manière transparente vers le modèle (Forwarding d'erreurs) sans masquer le contexte via des erreurs 500 génériques.
