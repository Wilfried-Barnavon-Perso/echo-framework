7c. Cognition Profonde & Base vectorielle des souvenirs

Pour ne pas être qu'une simple calculatrice amnésique, ECHO s'appuie sur une architecture mémorielle duale — un RAG organique persistant et un RAG éphémère de session — couplée à un moteur de routage cognitif dynamique.

Fiche d'Identité Technique

🧠 Cognition & Base vectorielle des souvenirs

Nature : Arsenal de mémorisation vectorielle (RAG dual) et Orchestrateur de Sous-Modèles.

Source : 12-owui-tools/memory_and_rag_tool.py (v2.1), 12-owui-tools/cognitive_agents.py.

Rôle : Assurer la persistance à long terme des connaissances utilisateur (RAG organique) et l'indexation temporaire des contenus de session (RAG éphémère), tout en orchestrant le routage dynamique (LITE/FLASH/PRO) selon la complexité de la tâche.

Exécutant : Processus Python async (Backend OWUI) couplé à une base vectorielle Qdrant.

Interconnexions :

  • Stockage organique : Collection echo_memory — vecteurs 1024d (bge-m3), partitionnement par user_id.
  • Stockage éphémère : Collection echo_ephemeral — vecteurs 1024d, partitionnement par user_id + chat_id + slug.
  • Embedding : Worker Docker local echo-embedding-worker (BAAI/bge-m3, 1024 dimensions, Distance Cosinus).
  • Distillation : EchoGeminiClient.call_distillation() — Gemini Flash pour extraction slug/tags.

💡 Comprendre l'Architecture Mémorielle Duale

ECHO dispose de deux systèmes RAG distincts qui répondent à des besoins différents. Le RAG Organique est la mémoire long terme : les faits importants, préférences et décisions y sont stockés définitivement et accessibles dans toutes les sessions futures. Le RAG Éphémère est la mémoire de travail de la session courante : résultats d'analyses, contenus de navigation web, données intermédiaires — tout ce qui est utile maintenant mais sans valeur au-delà de la session. Ensemble, ils compensent la Vallée de la Mort Contextuelle qui rend les informations distantes inaccessibles quand le contexte sature.

1. Architecture des Deux RAG

Les deux RAG sont physiquement séparés dans Qdrant — deux collections distinctes, deux cycles de vie différents, six outils dédiés dans memory_and_rag_tool.py.

Propriété RAG Organique RAG Éphémère
Collection Qdrant echo_memory echo_ephemeral
Outils d'écriture save_memory save_session_context
Outils de lecture search_memory, list_memory_topics search_session_context
Outil de suppression forget_memory Purge automatique fin de session (Admin Manager)
Scope de partitionnement user_id user_id + chat_id + slug
Durée de vie Permanent, multi-sessions (TTL configurable) Session courante uniquement
Usage typique Préférences, décisions, contraintes techniques, règles Résultats d'analyse, navigation web indexée, données intermédiaires
Reranking par importance ✅ Oui — MEMORY_IMPORTANCE_WEIGHTS ❌ Non — score cosinus brut, filtre sur slug

2. Les Six Outils Mémoire

Tous les outils sont définis dans memory_and_rag_tool.py (classe Tools) et exposés au modèle via OWUI. Leurs docstrings constituent la source d'instruction principale pour que le modèle sache quand et comment les utiliser.

A. save_memory — Mémorisation Long Terme

Sauvegarde définitivement un fait en mémoire long terme. Le flux de traitement est le suivant :

Pipeline save_memory
1. Distillation (EchoGeminiClient.call_distillation)
   → Gemini Flash génère un JSON {"slug": "...", "tags": [...]}
   → slug: identifiant court et technique (ex: "pref-python-312")
   → tags: 2-3 mots-clés sémantiques

2. Vectorisation (EchoGeminiClient.generate_embedding)
   → Worker local bge-m3 → vecteur 1024 dimensions

3. ID déterministe (UUIDv5)
   → uuid5(user_id + slug) → anti-doublons : un même fait est toujours
     le même point vectoriel (upsert idempotent)

4. Upsert Qdrant (collection echo_memory)
   → Payload stocké : user_id, chat_id, slug, summary (le fait brut),
     memory_importance (1→5), tags, timestamp

Le paramètre importance (entier 1→5) détermine le poids de reranking lors des recherches :

Niveau Label Poids de reranking Usage typique
1Trivial× 0.55 (pénalisé)Préférences légères, anecdotes
2Mineur× 0.75Informations utiles mais non critiques
3Utile× 1.00 (référence)Décisions, faits importants [défaut]
4Majeur× 1.30Contraintes majeures, ressources critiques
5Axiome× 1.70 (fortement boosté)Règles absolues, vérités fondamentales

💡 Propriété clé du reranking

Un Axiome (lvl 5) avec un score cosinus de 0.60 bat un Trivial (lvl 1) avec un score de 0.85 : 0.60 × 1.70 = 1.02 > 0.85 × 0.55 = 0.47. Cette asymétrie garantit que les règles fondamentales remontent toujours, même quand elles ne sont que vaguement similaires à la requête.

B. search_memory — Recherche Sémantique Long Terme

Recherche dans la collection echo_memory les faits mémorisés lors de sessions précédentes ou de la session courante.

Algorithme de recherche avec reranking
1. Vectorisation de la requête (bge-m3, mode "query")
2. Recherche Qdrant avec over-fetch ×3 :
   → limit = demandé × 3, score_threshold = 0.35 (seuil abaissé)
   → filtre : user_id = user courant
3. Reranking : score_pondéré = cos_score × MEMORY_IMPORTANCE_WEIGHTS[importance]
4. Filtre final : score_pondéré ≥ SCORE_THRESHOLD (défaut valve : 0.45)
5. Sort décroissant, retour des N meilleurs

C. list_memory_topics — Index des Souvenirs

Effectue un scroll sur la collection echo_memory (sans vectorisation) et retourne la liste de tous les slugs, tags et niveaux d'importance mémorisés pour l'utilisateur. À utiliser avant un forget_memory pour connaître le slug exact.

D. forget_memory — Suppression Ciblée

Calcule l'UUIDv5 déterministe à partir de user_id + slug et supprime le point correspondant dans echo_memory. Irréversible. N'affecte pas le RAG éphémère.

E. save_session_context — Indexation RAG Éphémère

Indexe un texte arbitraire dans la collection echo_ephemeral, scoped à la session courante (user_id + chat_id + slug). Le texte est découpé automatiquement en chunks sémantiques via EchoGeminiClient.index_text_in_ephemeral_rag().

Paramètres de save_session_context
text : str   → Texte à indexer (longueur quelconque, découpé en chunks)
slug : str   → Identifiant court unique (ex: "analyse-pr42", "rapport-tva-2025")
              → Servira de clé de filtrage pour search_session_context
              → Doit être unique dans la session pour ce contenu
Retourne : nb de vecteurs créés + confirmation du slug

F. search_session_context — Recherche RAG Éphémère

Recherche sémantique dans la collection echo_ephemeral, filtrée par user_id, chat_id et slug. Retourne les 5 extraits les plus pertinents. Disparaît à la fin de la session.

3. La Vallée de la Mort Contextuelle & Compensation par RAG

🏔️ Définition : Vallée de la Mort Contextuelle

Quand le contexte d'une session dépasse ~30% de la fenêtre maximale, les informations des premiers tours de parole deviennent effectivement inaccessibles au modèle — elles sont techniquement dans le contexte mais leur poids d'attention devient négligeable face aux tokens récents. Au-delà de 50%, cette dégradation est critique.

Les deux RAG constituent la réponse architecturale à ce phénomène :

  • Compensation proactive (RAG éphémère) : Dès qu'un résultat intermédiaire important est produit (analyse, calcul, extraction), le modèle l'indexe via save_session_context avant que le contexte sature. Plus tard dans la session, search_session_context le retrouve avec précision sémantique, indépendamment de sa position dans l'historique.
  • Compensation réactive (RAG organique) : Pour les informations des sessions précédentes (préférences, décisions, contraintes), totalement absentes du contexte, search_memory est le seul canal d'accès. Le reranking par importance garantit que les faits critiques remontent même avec une faible similarité sémantique.

4. Architecture de l'Ajustement du Niveau Cognitif (Le Cortex)

Le Pipe Engine (pipe_engine.py) injecte dynamiquement un outil virtuel invisible pour l'utilisateur : new_cognitive_level. Cet outil permet au modèle actuel de modifier sa propre puissance de calcul.

Mécanique de l'Escalade & Redescente

Trois niveaux sont disponibles, avec une philosophie de conservation des ressources :

  1. MODEL_LITE (Réflexe) : Point d'entrée par défaut en mode AUTO. Salutations, extractions simples, culture générale.
  2. MODEL_FLASH (Exécution agentique) : Moteur de travail principal pour toutes les tâches non-triviales : navigation web, scripting, synthèse, orchestration d'outils. Flash est capable, pas intermédiaire.
  3. MODEL_PRO (Expertise — dernier recours) : Uniquement si Flash manifeste une incapacité avérée. Architecture complexe, refactoring multicouche, raisonnement philosophique profond.

La Loi de Corrélation Contextuelle s'applique : si le contexte dépasse 50% de la fenêtre, un passage en MODEL_PRO est impératif pour maintenir la cohérence — indépendamment de la complexité de la tâche. Les deux RAG atténuent ce besoin en permettant de décharger l'information hors du contexte.

B. Délégation Explicite (Expertise Conseil)

L'outil delegate_reasoning (dans cognitive_agents.py) permet à l'orchestrateur de déléguer consciemment une portion de la tâche à un sous-modèle. Le résultat est réinjecté comme une donnée isolée, authentifiée par des ThoughtSignatures uniques. La délégation est strictement stateless : le sous-modèle ne possède aucune mémoire des tours précédents — le paramètre context est obligatoire pour lui injecter les faits nécessaires.

Modèle Cible Niveau de Pensée Usage Recommandé (Délégation)
MODEL_PRO PRO_THINKING (HIGH) Debug de fichiers multiples, Planification multicouche.
MODEL_FLASH FLASH_THINKING (HIGH) Formatage JSON complexe, Traduction sémantique riche.
MODEL_LITE LOW Distillation de texte brut, Résumé de documents volumineux.

5. Base vectorielle des souvenirs V2 : Cycle de Vie & Gouvernance

A. Gouvernance des Données & TTL (Time To Live)

Chaque souvenir dans echo_memory possède une durée de rétention configurable par niveau d'importance via le Dashboard Admin Manager :

  • Niveau 1 (Trivial) : Souvenirs éphémères et informations de passage.
  • Niveau 2 (Mineur) : Contexte de session étendue.
  • Niveau 3 (Utile) : Préférences techniques et noms de projets.
  • Niveau 4 (Majeur) : Logique métier stable et décisions d'architecture.
  • Niveau 5 (Axiome) : Règles de sécurité et Principes ECHO fondamentaux.

La purge de la collection echo_ephemeral est déclenchée automatiquement par l'Admin Manager (nettoyage des sessions terminées).

B. Consolidation Automatique des Souvenirs (Centroïde Vectoriel)

Après la purge TTL, l'Admin Manager exécute une consolidation des souvenirs Triviaux (Niveau 1) quand leur nombre dépasse un seuil configurable (défaut : 10 par utilisateur).

Pipeline de consolidation (Admin Manager)
1. SCROLL lvl1 with_vectors=true
   → Récupération des points avec leurs vecteurs complets (aucun appel embedding)

2. CLUSTERING GREEDY (seuil cosinus configurable, défaut : 0.75)
   cos(A,B) ≥ 0.75  → B rejoint le cluster d'A
   Taille cluster ≥ min_cluster_size (défaut : 3) ✓

3. CALCUL DU CENTROÏDE (dimension par dimension, Python pur)
   centroïde[i] = moyenne(vecteurs du cluster)[i]
   Re-normalisation L2 → vecteur_final (sphère cosinus, valide pour Qdrant)

4. CRÉATION DU POINT FUSIONNÉ (lvl2)
   summary : concaténation COMPLÈTE de tous les textes (aucune troncature)
   memory_importance : 2 (promotion lvl1 → lvl2, poids 0.55 → 0.75)

5. SUPPRESSION des anciens points lvl1
   Résultat : N points lvl1 → 1 point lvl2

🏛️ Principe : Respecter le Jugement du LLM de Distillation

La consolidation automatique est délibérément limitée aux souvenirs Triviaux (Niveau 1). Les niveaux Utile (3), Majeur (4) et Axiome (5) ont été assignés intentionnellement par le LLM de distillation — une promotion automatique contournerait ce jugement. La transition Lvl2 → Lvl3 est discutable pour la même raison. Seul le niveau Trivial, par nature incertain, justifie une consolidation autonome.

C. Interaction Cortex / Registre

L'IA utilise les outils de memory_and_rag_tool.py pour interroger ses deux registres. Le modèle décide quand il a besoin de contexte historique (RAG organique) ou de contenu de session (RAG éphémère), évitant ainsi le bruit dans la fenêtre de contexte active.

Action UI : Purge Granulaire

Pour une gouvernance totale, l'utilisateur peut déclencher manuellement l'action ECHO Memory Purge. Elle permet de visualiser les catégories de souvenirs (tags) triées par importance et fréquence, de sélectionner des plages de données (ex: 1-5, 8) et de procéder à un oubli sélectif sécurisé via un mode Dry Run (prévisualisation des impacts).
