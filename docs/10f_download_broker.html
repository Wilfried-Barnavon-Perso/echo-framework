10f. Download Broker

Le Download Broker (25-docker-download-broker/download_broker.py) est un service autonome (Daemon) chargé de l'ingestion asynchrone des fichiers téléchargés depuis le web par l'Agent Navigateur. Il opère indépendamment du flux cognitif principal pour prévenir tout blocage IO.

Architecture et Fonctionnement

Le Download Broker fonctionne en tant que Worker Docker isolé sans port exposé. Il boucle de manière asynchrone (polling) sur le répertoire des téléchargements partagés (/app/browser-data/downloads) et traite les éléments selon la logique suivante :

  • Garbage Collection : Si le chat associé (ID de conversation) n'existe plus dans le Vault de l'utilisateur, la branche de téléchargement est identifiée comme morte et purgée (shutil.rmtree).
  • Déplacement Atomique : Les fichiers valides sont déplacés du répertoire temporaire vers le Vault global de l'utilisateur via shutil.move().
  • Leurre Symbolique : Afin de lier le fichier à la conversation active sans dupliquer la donnée, un lien symbolique (os.symlink) est créé dans le sous-dossier de la session.
  • Sérialisation SQLite : Une fois le fichier validé et placé, le Broker détermine son MIME via get_gemini_mime et met à jour l'état cognitif via EchoStateManager, définissant le statut sur PENDING_INGESTION.
Découplage des ressources : Cette architecture garantit que ni le Pipe, ni le navigateur headless ne s'encombrent du traitement des transferts disques locaux, et assure la persistance des résultats d'exploration Web dans le système documentaire unifié d'ECHO.
