9k. ECHO N8N Orchestrator

N8N Worker (Sandbox & Démon)

L'outil n8n_orchestrator_tool.py est le pont entre l'agent ECHO et le sous-système N8N Worker (Tier 2). N8N s'exécute de manière "Headless" sur SQLite (volume echo-n8n-data) via l'image n8nio/n8n native, adossée à Node.js.

Règles d'Architecture strictes

  • Sandbox Éphémère : Tout workflow testé dynamiquement par le modèle (pour résoudre un problème temporaire) doit OBLIGATOIREMENT démarrer par le nœud Execute Workflow Trigger. Le mocking de payload asynchrone est impératif pour simuler les Webhooks/Emails lors des tests LLM. Les exécutions synchrones étant limitées, le repli vers le mode asynchrone est souvent nécessaire.
  • Déploiements Permanents (Mode Démon) : Réservés aux webhooks de production et crons, destinés à tourner en arrière-plan indéfiniment. Ces workflows interagissent avec les outils externes.
  • Child Chats & MCP : Les workflows N8N en mode Démon agissent comme des clients MCP, requêtant les services d'ECHO et ouvrant asynchronement de nouveaux "Child Chats" dans le système ECHO pour exécuter des tâches LLM complexes avec traçabilité.
  • Identité & Secrets : L'usage en dur de tokens d'API ou Headers sensibles (Cookie, Authorization) dans les nœuds est strictement proscrit. L'outil exige l'usage de la macro __ECHO_SECRET_... qui est résolue via l'Identity Vault.
