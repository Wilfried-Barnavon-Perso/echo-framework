Cette section constitue la référence de bas niveau du framework ECHO v5 : spécifications réseau, schémas SQL complets, inventaire des volumes Docker, collections Qdrant et dictionnaire des valves de configuration.

Topologie Réseau (Domain-Driven IPAM) et Ports

ECHO orchestre un cluster de conteneurs sur deux réseaux Docker isolés (echo-network en 10.20.40.0/24 par défaut et echo-sandbox en 10.20.50.0/24 pour le Coding Worker), régis par stack-echo.yml et bunkerweb-stack.yml. Les briques Core utilisent la plage .100–.103 et les Workers ECHO calquent leur dernier octet IP sur le numéro de leur dossier source (.20–.32).

Tables Complémentaires (call_bridge, rich_payloads, plans, codex_docs, cognitive_threads)

  • call_bridge : Pont entre un call_id d'outil (signature, function_name, args_json) et son résultat au sous-tour suivant.
  • rich_payloads : Stocke les parts enrichies (rich_parts_json) indexées par invariant_hash.
  • plans & codex_docs : Tables de suivi utilisées par le Planificateur Stratégique et l'Éditeur Codex.
  • cognitive_threads : Stocke l'historique des délégations multi-agents (Conseil Delphi & Sous-Agents) par (sub_sid, step_index).

Transport HTTP/2 et En-têtes Antigravity

EchoGeminiClient utilise httpx avec l'option http2=True (dépendance h2 obligatoire). Pour les requêtes vers l'API Code Assist, les en-têtes reproduisent l'identité de la plateforme Linux Docker émulée :

En-têtes - ECHO API Code Assist (Antigravity 2.5.5)
User-Agent: antigravity/2.5.5 linux/amd64
x-goog-api-client: antigravity/2.5.5
Authorization: Bearer {oauth_token}
Content-Type: application/json

Réseau et Furtivité

Les requêtes web orchestrées par le Cortex s'appuient sur des connexions HTTP/2 strictes couplées à l'injection d'en-têtes de navigation haute fidélité (get_stealth_headers), simulant un navigateur réel lors des investigations agentiques.
