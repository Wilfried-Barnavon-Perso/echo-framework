# 🌌 ECHO Framework - Connaissance Sémantique : `23-docker-mcp-broker`

> **ATTENTION AGENTS** : Ce document est la base de connaissances sémantique exclusive du dossier `23-docker-mcp-broker`. Il complète les règles globales définies dans le `AGENTS.md` à la racine.

## 1. Rôle du Dossier

Ce dossier contient le **MCP Broker** (Model Context Protocol). Il s'agit d'un serveur natif isolé dans son propre conteneur Docker. Son rôle est d'exposer des outils externes sécurisés au modèle via le protocole standardisé MCP sur le port **8000** (StreamableHTTP).

## 2. Cartographie des Fichiers et Algorithmes

### `server.py` (v6.11.0.1) & `core/cache_manager.py` (v5.231.20.1)
Fichier d'entrée du Broker instanciant le serveur `FastMCP` propulsé par `Uvicorn`.
- **Sémantique ASGI & Proxy** : Le serveur expose ses outils via le protocole natif MCP (`streamable-http` sur `/mcp`) ainsi que les routes REST `/schemas` (incluant le schéma `"ssh"` dans `SERVICE_SCHEMAS` sous `category: "orchestration"` pour le coffre `Identity Vault` via `EchoVaultTab.svelte` & `ssh_executor` et la précision `Google People API [Contacts]` sur `google_workspace`), `/proxy_mcp`, `POST /upload_drive` (streaming brut vers `provider.upload_file_stream` via `_build_broker_exception_response`) et `/health`. Il agit comme un **Proxy HTTP complet** sans accès direct aux bases de données d'Open WebUI.
- **WebUI User Middleware (`WebUIUserMiddleware`)** : Middleware pur ASGI interceptant les en-têtes HTTP `x-openwebui-user-id` (fallback `x-echo-user-id`), `x-openwebui-chat-id` (fallback `x-echo-chat-id`) et `x-echo-credentials` (Base64 JSON) afin d'injecter l'identifiant utilisateur, l'identifiant de conversation et les secrets dans les `ContextVar` `user_id_var`, `chat_id_var` et `credentials_var` (`core/security.py` v5.231.37.1).
- **Cache Manager** : `core/cache_manager.py` met en cache les résultats d'exécution des outils par empreinte MD5 préfixée par `user_id` (`{uid}_{tool_name}_{arg_str}`) dans la base SQLite locale `/app/data/mcp_cache.db` (table `cache_entries`).

### `core/` & `modules/`
Dossiers contenant la logique métier des outils exposés par le Broker.
- **`core/security.py` (v5.231.37.1)** : Maintient le contexte de sécurité asynchrone (`user_id_var`, `chat_id_var` et `credentials_var`) injecté par le middleware et `/proxy_mcp`, servant de support sécurisé multi-user et multi-chat au proxy et aux outils natifs sans connexion directe à une base de données.
- **`modules/m3_corporate.py` (v5.231.20.1)** (Corporate Sirene/Bodacc) : Intégration active (via `httpx`) avec les API d'entreprise de l'Etat pour la récupération légale d'entités et prise en charge optionnelle du token `sirene_key` par utilisateur (`credentials_var`).
- **`modules/m4_academic.py` (v5.229.1.1)** (Academic) : Connecteurs réels asynchrones (`httpx`) vers arXiv ou d'autres bases documentaires pour la recherche scientifique structurée.
- **`modules/m2_jobs_omnisearch.py` (v5.231.20.1)** (Omnisearch Jobs) : Mécanismes d'interrogation multi-sources (APEC avec pacing humanisé séquentiel et absorption DataDome, LinkedIn avec filtrage dynamique de séniorité `f_E`, France Travail OAuth2 v2 persisté par utilisateur `ft_token_<uid>.json` sur volume `echo-mcp-cache`, et Welcome to the Jungle WTTJ via index Algolia officiel et extraction O(1)) avec résolution prioritaire des secrets depuis `credentials_var`.
- **Adaptateurs de Fournisseurs Résidents (`modules/m5_providers.py`, v6.11.0.1)** : Isole la logique de cycle de vie spécifique aux fournisseurs MCP résidents derrière le socle factorisé `MCPServiceProvider` (`sync_credentials`, `prepare_env`, `after_list_tools`, `before_tool_call`, `after_tool_call`, `unwrap_tracking_url`, `clean_html_to_text` via BeautifulSoup, `_compact_tools_catalog`, `_build_broker_download_payload`, `_rewrite_result_with_broker_downloads`, `_make_tool_response`, `_publish_file_to_broker`, `_UPLOAD_SEMAPHORES`, `_UPLOAD_TARGET_LOCKS`, `_stream_resumable_put` PPCM 5 MiB, `_abort_resumable_session`, `upload_file_stream`) et l'exception partagée `AuthRequiredError`. Route de manière atomique tous les téléchargements de fichiers et pièces jointes vers le **Download Broker** (`/app/downloads/<user_id>/<chat_id>/mcp/<fid>_<filename>`, écriture `.part` + `chmod 0o666` + `mtime = now - 5.0` + `os.replace`) :
  - **`Microsoft365Provider`** : cloisonne les caches MSAL par tenant/client via `_compute_ms_sig` dans `/app/mcp_cache/microsoft_365/<user_id>/<ms_sig>` (volume `echo-mcp-cache`) via `sync_credentials` avec migration *zero-downtime* depuis le cache legacy et écriture `.cred_config.json`, et dirige `env["HOME"]` vers ce répertoire dans `prepare_env`. Sérialise les appels MSAL via `_TOKEN_LOCKS` (`_get_token_lock`), borne la concurrence Graph par boîte mail via `_MAILBOX_SEMAPHORES` (`Semaphore(2)` via `_get_mailbox_semaphore`, relâché avant `asyncio.sleep`) et déduplique les chargements de dossiers via `_FOLDERS_INFLIGHT` (`asyncio.shield`). Factorise `_parse_bool`, `_quote_graph_id`, `_create_graph_client` (transport IPv4 `local_address="0.0.0.0"`, `retries=0`, `timeout_sec=15.0`, `connect=6.0`), `_graph_request` (client HTTP frais à chaque tentative, support `json_body` et `follow_redirects`, récupération du HTML complet sans `Prefer: outlook.body-content-type="text"`, omission de `$skip=0`, garde `$select` `"from"` + `"bodyPreview"` et boucle de retry sur `(httpx.TimeoutException, httpx.NetworkError)`, `429` et HTTP $\ge 500$), le formatage et la capture unifiée d'exceptions (`_format_exception`, `_handle_tool_exception` remontant `AuthRequiredError` en `status="auth_required"`), le `$select` Graph (`_get_email_select_fields`), la normalisation/troncature des messages (`_normalize_email_message` convertissant le HTML via `clean_html_to_text` en préservant les liens/boutons et en décodant les SafeLinks), et le rafraîchissement MSAL asynchrone `_get_access_token_async` via `asyncio.to_thread` (sans fallback silencieux inter-comptes et levant `AuthRequiredError`). `_fetch_all_mail_folders` (paginé via `_fetch_paged_folders` sur `@odata.nextLink` jusqu'à 10 pages) et `_get_cached_folders` (`raise_on_error=True`, avec propagation de `credentials` à `_resolve_folder_id`) remontent une erreur explicite (`is_error=True` sans retour `[]` silencieux dans `list_mail_folders`). Dans `after_list_tools`, retire `flow_cache` de `complete_authentication`, rend optionnels `download_path`/`save_path`, injecte `body_max_length` sur `get_email` et `search_emails`, injecte les outils virtuels `list_mail_folders`, `trash_email`, `batch_trash_emails`, `batch_get_emails`, met à jour les descriptions de `search_emails`, `search_files`, `search_events` et `unified_search`, patche `list_emails` (`skip`, `order_by`, `body_max_length`, `include_body` avec `default: False`), appose un avertissement Hard Delete sur `delete_email`, et compacte le catalogue via `_compact_tools_catalog(optional_props={"account_id"}, max_desc_len=280)`. Dans `before_tool_call`, appelle `sync_credentials`, résout strictement `explicit_arg_id` vs `vault_acc_id` contre les comptes MSAL en cache (sans écrasement silencieux d'un compte différent), court-circuite `list_emails` (avec repli automatique sur `/v1.0/me/messages` filtré par `parentFolderId`, `$orderby` + retry `InefficientFilter` et tri `_sort_email_messages`), `search_emails` (`body_max_length` honoré, mode KQL `$search` à `fetch_top = min(limit*2, 100)` + filtre temporel précis + tri Python + troncature `[:limit]`, mode OData avec `ConsistencyLevel: eventual` uniquement en KQL et repli sans `$orderby` sur `400 InefficientFilter`), `search_files`, `search_events` (`calendarView` ou `/me/events` sur borne unique `iso_start`/`iso_end`) et `unified_search`, `get_file` et `get_attachment` (incluant `isInline`, téléchargement `$value` pour `itemAttachment` et erreur explicite `sourceUrl` pour `referenceAttachment` via `_build_broker_download_payload`) vers le Download Broker. Dans `after_tool_call`, sauvegarde et occulte `_flow_cache` brut de `authenticate_account` dans `.microsoft_mcp_device_flow.json` scopé par `credentials`. Implémente `upload_file_stream` via Graph v1.0 (`/content` pour 0 octet et `createUploadSession` + `_stream_resumable_put` pour `> 0` octet).
  - **`GoogleWorkspaceProvider`** : rafraîchit le jeton OAuth2 Google en mode Fail-Closed via `_refresh_google_access_token` (cache `_GOOGLE_TOKEN_CACHE` + verrou `_GOOGLE_TOKEN_LOCKS` et contrôle de scopes requis) réutilisé dans `prepare_env` (lève immédiatement `AuthRequiredError` en cas d'échec HTTP/`invalid_grant` sans écrire de jeton factice), l'injecte dans un répertoire temporaire via `WORKSPACE_MCP_CREDENTIALS_DIR`, et isole `WORKSPACE_ATTACHMENT_DIR` dans `_SESSION_STAGING_DIRS[cache_key]` avec nettoyage automatique `stack.callback` à la fermeture du process Stdio. Dans `after_list_tools`, compacte le catalogue (`_compact_tools_catalog`, `user_google_email` optionnel `"Auto-injected."`, `max_desc_len=115`). Dans `before_tool_call`, supprime `account_id` des arguments (prévenant tout crash FastMCP) et auto-injecte `user_google_email` depuis `USER_GOOGLE_EMAIL` du Vault s'il est omis. Dans `after_tool_call`, intercepte toute fuite de flux interactif local ou scope insuffisant (`OAUTH_ERROR_MARKERS` étendu avec `"Permission required for"` et `"insufficient authentication scopes"`) pour lever `AuthRequiredError`, collecte uniquement le répertoire staging de la session courante, nettoie le suffixe UUID4 (`_WORKSPACE_UUID_SUFFIX_RE`), déplace atomiquement chaque fichier vers `/app/downloads/<uid>/<cid>/<fid>_<filename>`, et réécrit `content` **et** `structuredContent` via `_rewrite_result_with_broker_downloads`. Implémente `upload_file_stream` via Google Drive v3 Resumable (`_GOOGLE_NATIVE_CONVERSION_MAP` pour conversion native optionnelle).
- **Remote Proxy (`modules/m5_proxy_mcp.py`, v6.7.18.1)** : Orchestrateur de requêtes MCP distantes (`sse`, `streamable_http`) ou locales (`stdio`) agnostique des fournisseurs, factorisant `_parse_and_validate_credentials`, appelant `provider.sync_credentials(user_id, credentials_dict)`, n'injectant plus aveuglément `account_id` dans `args`, propageant `chat_id` (`chat_id_var`), `credentials=credentials_dict`, `account_id=account_id` et `cache_key` (via `_open_transport` -> `provider.prepare_env` et `after_tool_call` avec repli `cache_key_preview`), et exécutant `before_tool_call` *avant* `_get_or_create_session` pour un court-circuit Graph Zéro-Stdio (déléguant également `after_list_tools(..., credentials=credentials_dict)` à `get_service_provider(service)`) :
  - **Cache de sessions (`_SessionHolder`)** : une session MCP par `cache_key` indexée sur `cred_hash` (`(user_id, service, cred_hash[:12])` via `_build_cache_key`) avec verrous par `cache_key` (`_get_session_lock`), détenue par une tâche propriétaire qui ouvre et ferme seule la pile AnyIO. Le démarrage est borné par `MCP_SESSION_START_TIMEOUT` (60 s), la fermeture par `MCP_SESSION_CLOSE_TIMEOUT` (15 s) et chaque appel outil/`tools/list` par `MCP_TOOL_CALL_TIMEOUT` (55 s, convertissant `asyncio.TimeoutError` en `TimeoutError` explicite).
  - **`TolerantClientSession`** : surcharge `validate_tool_result` et tolère les erreurs de validation du schéma de sortie (`RuntimeError`).
  - **Sérialisation** : `_dump()` utilise `model_dump(by_alias=True, mode="json", exclude_none=True)` pour restituer les champs en camelCase (`isError`, `structuredContent`).
  - **Éviction** : toute exception (`except BaseException:`, incluant `asyncio.CancelledError` et `TimeoutError`) entraîne le retrait de la session du cache sous `_get_session_lock(cache_key)` et sa fermeture protégée par `asyncio.shield(holder.close())`.

### `Dockerfile`
- **Build & Runtime** : Hérite de `echo-python-base:latest`. Embarque **Node.js 22.x LTS** (`setup_22.x`, patché CVE-2026-111497) et Git afin de supporter l'exécution sécurisée de serveurs MCP JavaScript/TypeScript (via `npx` / `node`) et de packages distants.

## 3. Dépendances Logiques
- Le MCP Broker est interrogé par l'outil `12-owui-tools/echo_mcp_tool.py` et le routeur `16-docker-echo-webui/backend/open_webui/echo/routers/vault.py` (`EchoVaultTab.svelte`) via ses endpoints HTTP REST (`http://echo-mcp-broker:8000/proxy_mcp` et `/schemas`).
- N'ayant aucun accès direct aux bases SQLite d'Open WebUI, il reçoit les *Credentials* (extraits en amont de `identity.db` par `echo_mcp_tool.py` via `EchoStateManager`) directement dans le corps de la requête `/proxy_mcp`, et monte le volume externe `echo-mcp-cache` sur `/app/mcp_cache`.
